# Recommendation regression checks

`recommendation_tests.cpp` compiles the production recommendation and API code directly. HTTP responses are injected, so tests do not access the network or depend on an installed game. Public API samples are kept in `fixtures` for schema and PP formula checks.

On Windows, use an installed Android NDK and the existing Docker Desktop WSL distro:

```powershell
pwsh ./tests/run.ps1
```

The runner discovers the NDK installed by QPM. Override its compiler with `-Compiler <absolute clang++.exe path>`. The static test executable targets x86_64 Android and runs in WSL; the actual mod build continues to target Quest arm64. For another WSL distro, pass `-Distro <name> -LinuxWorkspace <workspace mount path>`.

Checks cover timestamp parsing and recency, all supported response shapes, unique chart parsing, effective modifier stars, mixed-characteristic profile weighting, NF exclusions, both public PP formulas, histories beyond the old page caps, skipped/unrated rows, failed/incomplete pagination, cache reuse, later recommendation candidates, playlist song limits, empty/malformed clan membership, worker settings ownership, all 20 clear-rate steps, cautious target stars, merged gain sorting, and choosing the best chart before deduplication.

Personalized clan checks cover weighted insertion/replacement and displaced contributions, modifier PB baselines, tiny gains that break ties, the 1-weighted-PP progress floor, captured-map exclusions, minimum clear rate on replays, PPv3/PPv4 inverse capture targets, secondary-clan PB transfers and rival removal, best-chart selection, verification budgets and rotating exploration, untouched charts and later catalog pages, complete associated-score pagination, inconsistent totals, invalid numbers, partial verification failures, independent clan failures, cover fallback, and exploration cursor persistence. Playlist writer checks also verify hypothetical titles/descriptions with stable filenames and covers.

Optional legacy-mode checks cover its default-off worker setting, inclusive automatic maximum with no minimum, signed-gap ordering, PBs above/equal to predicted PP, retained improvements, modifier/NF PB eligibility, PPv3/PPv4 predictions, later-page replacements, pre-limit song deduplication, independent all-clan results, failed/repeated/changing/incomplete pages, successful empty results, and preservation of personalized search history. Writer checks switch legacy/personalized titles and descriptions in the same files while preserving clan artwork and hypothetical labels.

Legacy-cap checks verify the direct clearability boundary at every nonzero slider setting, tighter caps at higher thresholds, 0% disabling the cap, independence from personal PP values, failure-history influence, and selecting the highest qualifying region when the local model has multiple clearable regions. Personal recommendation star-range behavior is checked independently and retains its existing search window.

The test executable accepts `--audit-clan-profile <numeric-player-id> <response-directory>` for an optional public-data audit through the production clan implementation. Supply `manifest.tsv` rows as `response-filename<TAB>exact-request-url`, with UTF-8 JSON responses stored under that directory. Missing requests are written to `missing.txt` for separate collection; the audit itself does not use the network, import attempts, change playlists, or save search cursors. It prints per-entry personal PP, weighted clan gain, gap, clear estimate, and search coverage. Keep captured profiles under an ignored review directory rather than committing full player histories.

Refresh performance checks additionally cover screening-cache TTLs, restart persistence, corrupt/future/old-epoch cache rejection, exact PPv3/PPv4 metadata round trips, current PB and rival updates through warm caches, fresh verified ratings, at most two jobs, worker joining on exceptions, shared request pacing, per-path pagination limits, cross-clan rate-limit preservation, and aggregation of worker HTTP statistics.

Search-quality checks run consecutive saved refreshes with identical responses and advancing exploration. They verify that useful picks remain in direct competition with new discoveries, learned negligible contributions stop occupying the capture/progress quotas, real rival/PB changes remove obsolete picks, failed previous picks are retried, the verification cap stays fixed, and search state survives restarts. They also cover legacy cursor migration, invalid/old-epoch history, independent primary/secondary searches, primary-clan changes, and secondary PB transfers without double counting or recommending captures achieved by switching alone.

Use `--benchmark-clan-profile <id> <response-directory>` to compare uncached and cached production searches with recorded responses. It repages existing 100-row captures into 500-row responses without network access, counts logical requests and response bytes, and checks that warm caching preserves chart order and contributions. `--benchmark-paced-clan-profile` adds simulated 200ms request latency and enables production pacing/workers. Replay times include fixture I/O and are not headset measurements.

Accuracy checks cover monotonic weighted regression, cascading pools, recency and missing-date weights, equal-star observations, interpolation, empty and sparse profiles, endpoint holds and extrapolation limits, training exclusions, modified stars, input-order independence, and both recommendation modes on both leaderboards. A noisy-profile sweep verifies finite, bounded predictions that never increase as stars increase.

Account checks cover profile URL hosts and escaping, aliases and linked BeatLeader IDs, exact 64-bit ID parsing without floating-point rounding, ScoreSaber's minimum search length and nested rank fields, search pagination, duplicate display names, malformed/unavailable responses, superseded requests, cancelled searches, independent service state, and bounded PNG/JPEG avatar dimensions. They exercise production lookup/parsing/state helpers with injected HTTP responses. The actual settings UI and BeatLeader's signed-in export need on-device validation.

`playlist_writer_tests.cpp` additionally executes the production playlist writer against a workspace-local sandbox. It verifies combined playlist serialization and switching both directions between split and combined layouts, including preservation of other services, clan playlists, backups, and user playlists. The sandbox is removed after a successful run. A production build uses the ordinary Quest PlaylistManager directory; only the test compilation overrides its path.

Fixture sources, captured during review and fix verification in October 2026:

Attempt tests also cover real BeatLeader `/scoresstats` and ScoreSaber v2 `personalBest=all` responses, BeatLeader's sibling song/chart hash-lookup shape, clear/failure balance, practice/modifier exclusions, recency, chart-specific predictions, bounded chart influence, local/API deduplication, concurrency, damaged-file preservation, offline fallback, and ScoreSaber's documented-realm HTTP 400 workaround. Persistent test files use only `tests/attempt-sandbox`; successful runs remove their explicitly named fixtures.

Refresh tests verify that the two providers overlap, both workers finish before completion, failures remain independent, and disabled services do no work. ScoreSaber compatibility tests cover a single realm-parameter fallback across multiple pages, both query parameter positions, and rejection of ratings from other realms. `http_client_tests.cpp` exercises the production client through a fake libcurl boundary, checking connection reuse, thread ownership and cleanup, independent byte limits and timeouts, callback reset, HTTP/transfer errors and recovery, and per-thread diagnostics. These checks do not measure headset performance.

- BeatLeader public `/player/{id}/scores` and `/maps` responses, reduced to representative rows including FS and OneSaber. NF scores use `modifiers=NF`.
- `beatleader-ppv4.json`: 520 reference PP values generated with BeatLeader website commit `606b7f9d33fec7dcf2427cea1d1151b74a5ec006` (`src/utils/beatleader/rebalanced-pp.js`), plus three unmodified live API scores captured on October 27, 2026. Checks cover PPv4 parsing and per-chart version selection, dynamic curves, slider/length/note penalties, low-star behavior, and both recommendation modes. Legacy PPv3 fixtures remain unchanged. BeatLeader attempt-cache checks verify refreshing positive old ratings, reusing recent checks, resolving PB matches, and excluding outdated evidence after failed lookups.
- ScoreSaber public `/api/player/{id}/scores`, `/api/leaderboards`, and `/api/v2/leaderboards` responses. v2 uses `status=RANKED`, `realmId=1`, and star bounds.
- ScoreSaber `/api/v2/realms/1/pp-curve` for its published accuracy multiplier points.

Pagination metadata in reduced fixtures is adjusted to the retained row count. Synthetic cases supply deterministic mock pages, including network failure and invalid server responses. `.review/review_tests.cpp` is the historical pre-fix reproducer and intentionally asserts the old defects; use this suite for post-fix validation.

`https_smoke.cpp` is an opt-in real-network check of the source-built curl 8.23.0 / Mbed TLS 3.6.7 stack, separate from the offline suites. Configure `tests/https_smoke` with the Android NDK toolchain, `ANDROID_ABI=x86_64`, and `ANDROID_PLATFORM=24`, then build and run `rankedtools_https_smoke` from the repository root in Docker Desktop WSL. It checks both leaderboard APIs, plain-HTTP rejection, and invalid-CA rejection. Android's resolver service is unavailable in that WSL environment, so pass current Windows-resolved `host:443:ip` arguments for `api.beatleader.com` and `scoresaber.com`. URLs, SNI and certificate hostname verification remain intact. This test is not a headset test.
